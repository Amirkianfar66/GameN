Recorded 7 October 2026 by Backend/Integration on `codex/v1-lobby-identities`, base `c8856242caea349b620345349f6b59c7a87b6d7f`. This is a new decision record beside the frozen bootstrap register; no locked historical source is rewritten.

The immutable [Designer owner record](https://github.com/Amirkianfar66/GameN/blob/4fa2ff3db5edff97feefa7bc12b7f2b627275c34/docs/design/owner-decisions.md) records that approval. Integration selects the separately versioned identity document proposed in DSN-REQ-6. It leaves all strict protocol-2 game/lobby views, receipts, gameplay commands and rule pins unchanged. The [Designer catalog](https://github.com/Amirkianfar66/GameN/blob/ecbc0d703fa5e8b6b576e0b9eff6dc972761d3ea/design/contract/crew-catalog.json) is pinned at `ecbc0d703fa5e8b6b576e0b9eff6dc972761d3ea`, SHA-256 `ccc0ab8d484f934d9457a4a914191d85b8d9c914496ab1b4d329b6033aecb8d8`: `crew-0.1.0`, IDs `c1` through `c9`, proposed asset manifest `design-0.2.0` and tokens `0.4.0`. This change adopts only the identity IDs and operational selection rules; no art, token or asset version is adopted.

Names are player-typed public text, 1–12 Unicode code points, nonblank and without control characters or lone surrogates. They are preserved without normalization/truncation. They may duplicate another name or read like a role. Consumers render them as text with the seat number; a name supplies no role, authorization or styling rule. The code-point bound is an implementation choice matching the catalog's maximum; it is not a new game mechanic.

Only the authenticated active binding may set its own seat's pair. Character claims serialize transactionally, so two seats cannot hold one character. Choices may change in the lobby and are fixed at start or abort; they survive identity recovery with the seat. Role generation never reads name/character. Empty choices and historical missing documents preserve the numbered-token / “Player N” fallback; old clients may start without selecting identities. New clients should offer selection before start, and must never offer it after learning a role.

V1-01 still chooses Room A/B before roles are dealt. Its existing admission request remains unchanged. The relative character/name-versus-room UI order is not enforced here; Designer's DSN-D15 sequencing question remains a consumer integration detail. V1-01 through V1-21 remain approved, Original Powers remain off, and ruleset `in-person-v1-2026-10-06` / owner-overlay hash `6ca355ebf3553e24a16eae847f5b550b1d3da8bd0a2daf80f69ec94dd2809a90` is unchanged.

Frontend and Balance review of these additive contracts and their combined consumer remains required before adoption. Designer coordinates catalog/assets and fallback presentation. This implementation creates no selection UI, publishes no assets and performs no cloud deployment. API use and listener semantics are in the [Backend handoff](../backend/lobby-identity-handoff.md).

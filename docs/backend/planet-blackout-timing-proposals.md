# Blackout timing: two pending outcome proposals

**Status: reviewable proposals, not approved gameplay or implemented behavior.** The owner has settled the direction: the complete five-second lit / ten-second dark targeting window belongs before Jail voting. Neither outcome schedule below, nor its cancellation and physical-checkpoint consequences, has owner approval. Integration reviewed Proposal B as coherent and feasible; that is not outcome authorization. Keep the current runtime order until the owner explicitly selects a package.

The source baseline is `fb33cecbf4b0fc2bef5d107e79ae2aac0ed7be70`. Designer evidence is PR #207 head `d52a8ae94f7639dd853f04b4e897b9b77aecff42`. This document changes no runtime, contract, canonical authority, creation default or saved match. No gameplay tests or emulators were run for this documentation.

## Shared foundation

Both proposals finish ordinary turns and the final private conversation first, keeping voluntary movement and Captain commands closed and closing Hospital-panel submissions. If Blackhole is active, select one complete current reality uniformly, retain its pending actions and costs together, collapse pointers, and run the existing independent six-second presentation. Without Blackhole, skip that presentation. Never target, resolve a current-round Promise or evaluate an ending in a discarded/speculative reality. [1, 2]

Then open the same 15-second Blackout every normal round, including no-request/canceled-request rounds. Admit only retained Healthy/free requesters; cancel an ineligible **untargeted** request before admission without lifetime consumption. Bind admitted requesters to their current selected-world room and snapshot logical occupancy and health before the lit preview. Freeze coordinates for all five lit and ten dark seconds. Keep ordinary movement, commands and panel submissions closed. [3]

The first valid choice in `[dark start, window end)` locks and spends the lifetime use. Empty, own-character and already-Eliminated snapshot positions are consuming misses; an admitted timeout also consumes once, including disconnect. Invalid input does not lock or spend immediately. Exact retries recover the accepted choice. Capture both legitimate attempts before either causes damage; retain both when they select the same occupant. Persist the snapshot occupant identity or an explicit miss, never a later live-slot lookup. [3]

## Proposal A — target before voting, resolve after the result

**Pending.** This package preserves the existing combined attack/Rescue order while moving targeting.

> Turns and final talk → optional Sync + six-second presentation → five lit / ten dark targeting → full 60-second Jail vote → full five-second result → combined attacks, Rescue and normal finalization → navigation.

At the Blackout deadline, finalize choices/timeouts and their costs, then open a fresh full vote from its actual authoritative start. No Blackout damage/block outcome is published yet. Evaluate giver-only Meet A/B at this actual voting start. Apply Jail capacity, detention and office consequences normally, then show the complete result interval. [1, 4]

After the result, resolve retained actions in stored actor order, each role Main Action before its ordinary Shot, followed by Rescue, Round 3 Supply, due deaths, physical placement, permitted reveals and Clone expiry. Then evaluate No survivors and navigation/arrival under the current finalization rules. Existing Hospital healed-first/numeric admission remains within this combined stage. [1, 3, 5]

The target binding must survive the vote. If seat 3 selects the position occupied by seat 5 and the vote moves seat 5 to Jail, the strike still targets seat 5; it cannot acquire a replacement or miss because the old position is empty. A Disabler jailed after a committed choice/timeout remains spent and its valid strike survives. Actual target health/defenses are checked at impact. The earlier same-vote cancellation rule is therefore replaced by pre-admission cancellation only. This consequence needs approval; targeting placement alone did not approve it.

**Tradeoff:** this preserves the combined action and bed-allocation schedule, but players vote before seeing Blackout injuries/eliminations. Target identities must remain bound across Jail transfers.

## Proposal B — commit Blackout damage before voting

**Pending and technically feasible.** This package lets the vote respond to actual Blackout consequences.

> Turns and final talk → optional Sync + six-second presentation → five lit / ten dark targeting → committed Blackout damage and physical placement → full 60-second Jail vote → full five-second result → remaining attacks, Rescue and normal finalization → navigation.

At the Blackout deadline, resolve only the complete Blackout batch in stored actor order. An earlier strike incapacitating the other Disabler does not cancel their already-admitted attempt. Recheck target health and defenses: active Clone blocks without consuming Protection; otherwise active Protection blocks its first applicable attack; otherwise Healthy becomes Injured and Injured becomes Eliminated. Preserve Command immunity and no replacement/refund for a target already eliminated by an earlier effect. Do not process queued new Protection grants early or expire Clone here. [3]

Before publishing/opening voting, settle actual health, office and physical-placement consequences atomically. Every committed Injured player must occupy H1–H4; no persistent waitlist, fifth bed or Injured player left in A/B/Jail is valid. Existing bodies retain their slots. New injury/second-hit-body candidates compete in numeric seat order; denied admission uses the existing permanent offboard overflow treatment, including medical/detention/office cleanup and suppression of provisional clinical facts. Do not run queued Rescue, Supply or due-death aging at this checkpoint. [5]

**Earlier Hospital admission changes outcomes.** Later queued heals cannot be counted as free beds now. If four beds are occupied, a newly injured Blackout victim can overflow and be permanently eliminated even though a later queued Rescue would have freed a bed or healed that victim in the old combined stage. Earlier admitted Blackout patients/bodies also retain their beds against later ordinary-attack candidates. This changes the old single-stage healed-first/numeric competition and must remain explicit in the approval package.

Open a fresh full 60-second vote from the committed post-Blackout state. Rebuild existing eligibility: living players, including Injured/Jailed players, remain voters; Eliminated players do not. Living non-Jailed players, including Hospital patients, remain targets. Use the recalculated eligible count for the existing threshold. Evaluate giver-only Meet A/B here; injury/forced Hospital placement may make it Not fulfilled. [4]

Apply normal Jail admission and the complete five-second result. A selected Hospital patient stays physically in Hospital and gains detention/reservation only when capacity permits. Preserve the five-place accounting and unrelated patient reservations; a full Jail does not invalidate the ballot or its Promise. Later imprisonment cannot undo completed damage or restore a spent Disabler use. [1, 5]

After the result, resolve only the remaining actions, preserving their relative stored Main-before-Shot order and accepted fixed targets/costs even if their actors were incapacitated. Then resolve retained Doctor/panel Rescue, Round 3 Supply, due deaths, final placement, permitted faction reveals and Clone expiry. Rescue can heal a still-Injured victim after remaining attacks; it cannot revive an Eliminated/overflow-removed victim. Panel reservations settle only at their actual Rescue opportunity. New injuries retain the existing following-round rescue deadline; this adds no aging tick. Evaluate No survivors only after the relevant full finalization, then navigation/arrival. No new exception shortens the full vote/result intervals, including an empty electorate. [1, 6]

**Tradeoff:** damage informs voting, but all Blackout attacks now precede ordinary shots, changing defense consumption and possible injuries/eliminations. Earlier Hospital admission changes survival and bed priority. The new finalized checkpoint can also change offices, electorate, threshold, targets and Meet outcomes. The old Jail-cancellation rule cannot cancel an attack that has already happened.

## Implementation and checkpoint boundaries

The current lifecycle opens Blackout after Jail/result. Its registered action stores `boundRoom` and `selectedSlotId`; the physical resolver derives the occupant from live positions and rechecks requester eligibility. Merely moving the phase would break Proposal A's target persistence and could incorrectly cancel committed attacks. Both proposals need saved admission, frozen target/miss and terminal-attempt state. [7]

Keep completion evidence private and versioned, keyed by round/window and original request/attempt ID. Distinguish registration, final choice/timeout, lifetime charge and resolved outcome. Registration receipts are not proof of a hit. The appropriate deadline transaction must atomically commit costs, resolution state, authorized views and the next phase/outbox. Duplicate/stale deliveries must check the saved phase/token and completion marker, preventing double spending, damage, Protection consumption, publication or vote creation. Proposal A records the committed target before voting and its resolution after the result. [2, 7]

Proposal B needs a Blackout-only resolver plus the remaining-action resolver, sharing damage/defense and placement primitives. Today's complete `resolvePlanetPhysical` also processes ordinary shots, treatment, Supply, due deaths, reveals and expiry, then clears all actions. Calling it twice or calling it early and restoring queues would be incorrect. On the early commit, mark attempts resolved and remove only their pending `REQUEST_BLACKOUT` entries while retaining journal evidence; the later resolver must exclude them. [7]

At window opening, publish the selected post-turn/Sync targeting board so the shared lit preview matches the snapshot even without Blackhole. For Proposal B, publish a versioned **After Blackout** checkpoint that states ordinary actions and Rescue remain pending. It finalizes the completed batch, not the round or other registrations. Replace the whole neutral board snapshot atomically from canonical physical state; patching new beds onto a stale shared board can leave duplicate occupants/slots. Preserve faction reveal at the later normal checkpoint and exact roles/Code until authorized match end. These publication checkpoints are proposed changes, not existing authority. [1, 8]

Everyone receives the same lighting and deadlines regardless of requests/selections/misses. Picker controls and costs remain requester-private; publish no occupant map, requester count, hidden actor order, faction, branch metadata or route. Windows retain ordinary endpoint permissions during the lit preview, are unavailable throughout darkness, and reopen under ordinary permissions afterward. [3, 8]

Generic block audiences come from the target's actual physical room immediately before impact, not the remembered targeting room or a viewer's chosen panel. Include the target and retained bodies; exclude later entrants, outsiders, a nonparticipating host and the shared display. Deliver only the existing cause-neutral cue, with no grantor/resource/role disclosure. Buffer each complete batch, use canonical subject ordering and common checkpoint timestamps, and retain audience-scoped deduplication/freshness. Reconnect restores the current checkpoint/phase without replaying completed cinematics. [3, 8]

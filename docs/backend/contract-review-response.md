## Event subscription and reconnect

Listen to the caller's composed view and its authorized event collection only. Query public events with `audience.kind == public`; query player events with `audience.kind == player` and `audience.seatId == the admitted seat`. Rules require these constraints. Sort numerically by revision and ordinal in the adapter. There is no requirement that separate listeners deliver events before or after views.

Buffer a live event until its corresponding authorized view revision is present. If a newer snapshot has overtaken an event, update facts and skip obsolete cinematic playback. On subscribe/reconnect, obtain the fresh composed state first and establish a replay cutoff at its revision; retained older events are history, not instructions to replay animations. All first-slice events remain stored for the fixture lifetime; there is no pruning job. Production retention and event query/index choices require review before a production release.

A match ID or event/phase identifier must never encode a role, defense or private sequence. Secret registration does not rewrite public, target or other player view/event documents, including their Firestore update metadata.

## Adoption gate

Frontend must re-review the behavior guarantees, event-stream choice and deferred targeting/view work. Game Balance must independently review the slice's request/view usage and rule expectations. The backend PR remains unmerged pending those reviews and integration review. The emulator checkpoint does not establish connected device behavior, a complete round or complete V1.

# Playable vote and declared-Hack release

Tracked in [issue #134](https://github.com/Amirkianfar66/GameN/issues/134). The owner authorized completing Backend and Frontend integration, fixing remaining failures, and deploying the playable staging update once checks pass.

## Behavior and source

New matches use the approved five-second public vote result and private declared-side Hack: up to fifteen seconds to declare, five seconds to read the result, then sixty seconds to converse. These durations and visibility come from the authoritative game service. Undercover and Alien retain permitted bluffing; the client does not reveal the target's actual side.

The playable phone interface adopts Claude's phone kit and Hospital/Jail clothing. This continues the joined Frontend checkpoint `3dbc3699c7589d1031f5e2ca6b163e5cf150a246` and merges the complete Claude PR #127 source at `5c9a1510d35d4b9762f9bc2a27dae3f5d53bd5d7`. The original drawing sources, historical rules and Canvas snapshot remain evidence.

Only the pure wardrobe and phone-kit drawing modules cross into runtime, with a recorded source hash and exact derivative hash. Prototype controllers, fixtures and clocks remain excluded. Integration's action-coverage mapping adds the declared-side command from the phone-kit contract without rewriting historical capture inputs. All five art bundles load uniformly before private content.

## Immutable compatibility

The new `design-0.3.0` manifest records source, runtime and emitted bundle hashes separately from the Hosting build digest. Its supported gameplay tuple is:

| Field | Value |
| --- | --- |
| Protocol | `2` |
| Engine | `full-game-1.5.0` |
| Ruleset | `in-person-v1-declared-hack-2026-10-12` |
| Ruleset hash | `1d8a5e509372ea816af8d6782bf1d73720532ed672ee2f77e2938805976d8d6c` |
| Art | `design-0.3.0` |

Ready accepts this exact tuple only after the complete player bundle set has loaded. The previously reviewed 1.4/design-0.2.0 pair remains supported; crossed and unknown pairs fail closed. Receipt retries retain their original command identifiers and acknowledgments.

The engine's historical default remains 1.3. Production explicitly opts newly created matches into `MOTHERSHIP_NEW_MATCH_PROFILE=declared-hack-1.5`. Existing prepared deals preserve every stored pin. With the new profile enabled, previously unprepared 1.3-or-earlier lobbies use `MOTHERSHIP_LEGACY_ASSET_MANIFEST_VERSION=v1-preview-469bf64fe98cac5a`; stored 1.4 lobbies use `design-0.2.0`.
